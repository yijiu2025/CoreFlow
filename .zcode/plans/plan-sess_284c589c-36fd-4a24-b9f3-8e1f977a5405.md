## 背景说明

仓库中已存在 `docs/development/设备ID全链路梳理.md`（2026-09-02，205 行，由 95df9d6/81350f1 提交创建），已覆盖大部分链路。**本次不新建重复文档，而是把这份文档更新为完整版**：补齐它没覆盖的前后端部分，并扩充"存在的问题"。

## 探索发现的新内容（现有文档未覆盖）

1. **admin / poseadmin 前端完全没有设备 ID 逻辑**（无 localStorage、无请求头注入），现有文档只写了 oauth21/posecraft/firewall 三端。
2. **firewall 后端有独立指纹体系**：`src/app/firewall/util/fingerprint.js`（sha256(ip|ua|lang|enc)），与 device_id 体系无关，容易混淆，需要写清楚。
3. **`src/app/oauth21/services/device.service.js` 是 OAuth Device Authorization Grant（device_code 流）**，与"设备ID"无关，需加"勿混淆"说明。
4. **phonecopy 的真实状态比文档写的更微妙**：web 源码（`phonecopy/src/utils/auth.js`）确实没接共享包，但 `phonecopy/android/app/src/main/assets/public/` 里打包的是 posecraft 构建产物（含 shared-device 编译代码），Android 壳运行时实际带着 `cf_device_id` 逻辑。
5. **H5 签名与 deviceId 的关系**（已核实无矛盾）：头和 query 都带 `x-device-id`，但验签在头和 query 两层都排除它（`signature.js:81`）。
