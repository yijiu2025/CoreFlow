### 6. 追补：主题包目录口径写成规则 + 静态守卫

用户指出「themes 目录下按主题包区分，文件夹名字就是 id」，据此把这条隐含约定显式化。

**实现核对**（真源 = `themes/index.ts` 的 `buildRegistry()`，见 details §13）：

- glob 只扫**一层** `./*/index.ts` → **一个子目录 = 一个主题包，目录名就是 id**；
- **目录名覆盖包内 `meta.id`**（`meta: { ...pkg.meta, id }`）—— 因为 `theme.scss` 的选择器
  `html[data-mauth-theme='<id>']` 的属性值由目录名生成，包内写别的会让选择器落空；
- 目录名不合 `^[a-z0-9-]+$` / 缺 `index.ts` / 缺 `default` 导出 / 缺 `meta` → **一律静默跳过**
  （容错：一个写坏的主题不该让整页起不来）；只有 `theme.scss` 而无 `index.ts` = 残缺，样式被忽略；
- 🔴 **`themes/app/` 的隐式条件**：它没被当成 id 为 `app` 的主题，唯一原因是**没有 `index.ts`**
  （版式侧汇总文件刻意叫 `pages.ts`）—— 这是个"碰巧没坏"，谁加个入口就凭空多出假主题，已写进规则 + 变成断言。
