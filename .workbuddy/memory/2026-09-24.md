### 结构（最终）


## 22:05 修复：窄 iframe 里重置密码页自行切成手机端（真实宿主：posecraft 弹窗）

**现象**（用户报告）：`http://localhost:5176/posecraft/` 打开登录弹窗（iframe 加载 oauth21），
宿主窗口变窄后**只有重置密码页**跳成全屏手机端，登录/注册页都正常。

### 根因（分发器判定不一致）

宿主 `LoginModal.vue`：弹窗 `w-[856px] max-w-[90vw]`，iframe 列 `w-[480px]`，
src = `buildSsoLoginUrl()` → **`/mini-login?…&isMobile=false`**。

实测 iframe 内宽度随宿主收窄：宿主 1440px → iframe **854px**；宿主 ≤800px → iframe **718px（<768）**。

三个分发器 `view/web/<page>/index.vue` 的判定：

| 分发器 | 判定顺序 |
| --- | --- |
| login | `isMobile=true` → **`from=mini` \|\| path 含 mini-login** → 自动识别 → 桌面 |
| register | `isMobile=true` → **`from=mini` \|\| path 以 /mini-register 开头** → 自动识别 → 桌面 |
| forgot-password | `isMobile=true` → ❌**直接自动识别** → 桌面 |

⇒ forgot **漏了 mini 来源分支**：`MiniLogin` 的忘记密码链接传的 `fromLogin=mini`
（`{path:'/forgot-password', query:{...$route.query, fromLogin:'mini'}}`）被丢弃 →
窄 iframe 里被自动识别判成移动端。

### 修复

`view/web/forgot-password/index.vue` 在自动识别**之前**补一条：
`if (route.query.fromLogin === 'mini') return DesktopForgot;`
（与 `DesktopForgot.goToLogin` 早已在用的 `fromLogin` 语义对齐；三分发器现已都有 mini 分支。）

### 排查手法（值得记）

- **桌面浏览器直接开 `/forgot-password` 不复现**——必须真放进 iframe，且读
  **iframe 内容页的 `window.innerWidth`**（不是宿主的）。
- 交叉对照实验最有效：同一宽度下并排测 `/mini-login` 与 `/forgot-password`，
  前者桌面卡片、后者 `mauth-page` → 一眼定位到"就这个页面的分发逻辑不一样"。
- 桌面卡片根 class 是 **`.auth-viewport`**（不是 `.auth-container`），写关卡时别猜错选择器。

### 关卡（`verify-forgot-view.mjs` 新增 I 段，52 → **56** 条）

I1 窄 iframe(580px)+`fromLogin=mini` → 桌面卡片；I2 窄 iframe 无 fromLogin → 仍切移动端（防误伤）；
I3 宽 iframe(854)+mini → 桌面；I4 显式 `isMobile=true` 优先于 mini（优先级未破坏）。
**毒丸**：删掉 `fromLogin === 'mini'` 分支 → I1 立刻变红（mobile=true desktop=false），已验。
