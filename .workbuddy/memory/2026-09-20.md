## 删 src 根因二次深挖（01:26-01:40）—— 推翻gc结论，真凶=tsbx沙箱执行层

- 细读 sandbox 主日志（sandbox_20648_000.log）：git rm 命令的沙箱进程 tsbx-8752 在 01:03:00-01:03:15 发出 689 条 ModifyBackup（345 m + 344 d），覆盖 src 全目录，从目标所在目录 __tests__ 起按目录树递归遍历（尾到 utils/shared），44 文件/秒，与渐进删除逐秒吻合。
- 删除执行者不是 sandbox-cli-gc（它只是备份记录者），是 tsbx 沙箱本身在 DeleteFile；每个被删文件在 ~/.workbuddy/workspace/sessions/b20ca99b.../modify_backup/ 有完整内容备份（11.d.* 共 341 个）。
- 实测触发矩阵：git rm src/…=级联（5次复现）；git rm 根部/git rm migrations/…/POSIX rm src/…/豚鼠小仓 git rm src/…=均安全。结论：仅「tsbx 沙箱内 git rm src/ 路径」触发。
- 规避精确化：删 src 文件用 rm+git add -A（POSIX rm 已在 src 上实测安全）；恢复 git checkout HEAD -- src。MEMORY.md 已更新。

## E3 关卡复跑 + connectStandalone 有界化 + Docker/CI 落地（18:49–）

### E3 跨进程关卡复跑

- 首次跑 `scripts/verify/stats-aggregation.mjs` **挂 5 分 18 秒**被手动 kill（预期 ~8 秒返回）。

### 核心诊断（本方案与"再加一堆规则"的本质区别）

问题**不是"没人审查"，而是审查没有分层**，导致三种失效同时发生：
规则入口七零八落（同一条"导出放末尾"散在 eslint / 守卫 / 文档三处）、
本地闸门被关闭、**已有文档在说谎**。故第一原则：
**能自动化的绝不写进人工清单；写进人工清单的必须是机器结构上抓不到的东西。**

分级用「爆炸半径」而非主观严重度：L0 阻断 / L1 整改 / L2 建议 / **L3 风格由工具负责，明令禁止人工提出**。
