### 密码策略归属结论（产出 `docs/PLACEMENT-password-policy.md`）
- **放 `framework/auth` 是对的，不迁 oauth21**。前提不成立：`src/framework` 是跨业务基础设施、

### 经验
- **`verifyCookie` 这类「守卫用错单位」的缺陷，纯读代码极易漏判**（看起来有长度守卫、有 timingSafeEqual，

- 测试内联副本是**最高危信号**：四套测试各有一份与真身漂移的 `verifyCookie`，正好把 🔴-1 掩盖了。

- 修这类「返回值契约是 null」的函数时，**把整个函数体包进 try** 比逐个加守卫更稳，
  因为 `Buffer.from(...,'hex')`/`base64url` 的截断/抛错行为不如想象中可预测。

### 关键实现手法（**下次做大文件拆分直接复用**）
- **用 Node 脚本按行号切片**，不要手工复制 900 行（必然产生静默偏差）。脚本要点：
  1. 每个 range 声明 `[start, end, 期望首行]`，首行不符 / 末行非 `}` 立刻报错退出；
  2. **覆盖性断言**：所有切片 + 头部 + 导出块的并集必须覆盖全部非空行，未覆盖即报错；
  3. 用 `(old, new)` 片段做语义改写（本轮抽 `_revokeOneSession` ×4），并断言**每片段命中恰好 1 次**；
  4. 写完后校验「每个函数名在 4 个文件中各定义恰好 1 次」。
  这样 1409 行重构一次成型，无转写错误。
- **跨模块 re-export 必须带 `from` 子句**：`export { x } from './mod.js'`。裸 `export { x }` 只导出**本模块本地绑定**，
  跨模块写会报 `SyntaxError: Export 'x' is not defined in module`（本轮踩到，运行时报错才发现）。
- **注释里不要写 `from './xxx.js'` 这种字面量**：依赖图脚本的正则会把它当成真实依赖，
  于是 `session.js` 出现 `-> session.js` 自环 + `-> xxx.js` 假依赖。改成「带来源子句的跨模块 re-export 写法」这类描述。

## 23:45 请求级数据库查询审计（"一次请求最少查几次库"）

### 做法
- 静态梳理全局钩子链（`addHook` 全仓扫描）＋ **动态实测**：临时脚本 `createApp()` 起真实实例，
  用 `sequelize.options.logging = fn` 采集 SQL、`app.inject()` 发请求（无需监听端口），
  逐请求统计查询次数并打印原始 SQL。探针用完即删（`_dbprobe*.mjs`）。
- 关键技巧：伪造已登录态不必写业务库——直接 `getStore('session').set(sid, sessionData, ttl)`
  + `signCookie(sid, 0)` 组 sid cookie，用完 `delete(sid)`。设备 ID 用
  `generateServerSideDeviceId(UA)` 生成**格式合法**的值，否则会误导发 DB 降级分支（踩过）。
- `app.inject(opts)` 只能传一个参数（第二参是 callback，传 `{}` 会崩）；`app.log.level='fatal'`
  可压掉 Fastify 自带的 incoming/completed 日志。

### 结论（实测）
- 全局钩子链（monitor / auth onRequest / firewall / Guard preHandler）**全走 Redis + 内存，0 次 DB**。
  无 Cookie / 无效 Cookie / 未登录 401 / 404 均 **0 次**；已登录（Redis 命中）也 **0 次**。
- auth onRequest 的 4 个条件落点：`index.js:153 findUserById`、`index.js:191 loadUserPermissions`、
  `session.js:370` + `:424`（Redis 未命中降级）、`session.js:894 getSessionTokenDevice`
  （经 `device.js:186 loadFromDb`）。
- 唯一会"潜伏命中"的是 ④：**客户端无有效 device id 且 Redis session.deviceId 非法/缺失** → 1 次
  `session_tokens` 单查。正常浏览器（带合法 `x-device-id`）与"无 device id 但 session 合法"都是 0。
- Redis 会话丢失降级路径：1（`SessionToken.findOne` 带 JOIN User）+ 3（`loadUserPermissions`）= **4 次**。
- 业务 handler 自己的查询另计（`/user/v1/profile` 实测再 +1）。
