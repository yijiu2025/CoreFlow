## 第十轮：大模型「端点配置」（2026-10-07）

**需求**：`接口地址 + 模型 + token` 应**绑成一套**、可存**多套**（MiMo / DeepSeek …）、**手动切换**用哪套，
同一套内多个 token **自动轮换**（原有能力升级为按配置独立）。

**设计**：一套 = `{id, name, base_url, model, max_tokens, temperature, timeout, json_mode, note, api_keys[]}`；
落盘 `{active_profile, profiles[]}`；切换只动 `active_profile` 一个 id。
- **懒迁移**：老扁平结构按 `"profiles" in ov` 判分支，缺字段用**当期 env** 补
  （本机当时只有 `.env`、没有 `llm_settings.json` ⇒ 这是真实入口，不补就会在迁移瞬间丢 base_url/model）。
- 🔴 **Key 轮换状态按 profile 分桶**：`_KEY_STATE = {"pool": {pid: {idx, bad}}}`，
  `bad` 按 key **下标**记 —— 共用一份会串台（A 套的冷却污染 B 套，丢掉可用 key）。
- 🔴 **落盘只写新形态**，顶层扁平字段必须清掉；否则「删光配置」后会被迁移分支**复活**。
- 🔴 **扁平 payload（老前端）只合并进当前激活那套**，其余配置全量保留
  （原写法 `rows = [merged]` 会把其它端点删掉 —— 自测发现并加了断言）。
- **「使用中」= 从 `idx` 起第一个可用的 key**，不是 `idx` 指向那把（那把失效时会显示「没有 key 在用」）。
- `mask_key` **必须保尾部**：短 key（如 `sk-ds-1`）原先塌成同一串 ⇒ 回传时脱敏串反查**静默丢 key**。
