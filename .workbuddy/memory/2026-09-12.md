## 文件默认关闭 + 全局 log 注册 + 通道独立级别 → v0.4.0 / v0.4.1

用户三项要求（依次）：① 默认不该写文件，写文件必须手动配置；② `createLogger` 只要两个参数（tag + 是否注册全局），其余配置走 `config()`；③ `configureLog` 也要能开 `file`，且全局与模块同时开启时**不能重复记录**，不配也要有合理默认值。

### 最终 API 形态（重要约定）

```js
// src/app.js —— configureLog 全项目只调一次
configureLog({ level:'info', console:true, consoleLevel:'info',
  /* file: {...} 给对象即开启；注释掉 = 不写文件 */ });
const log = createLogger('app', true);   // 第二个参数 = 注册为全局 log
initLogErrorTraps();

// 业务文件
import { log } from '../../framework/log/index.js';   // 直接可用

// 单模块配置
const pay = createLogger('pay');
pay.config({ file: { name:'pay', level:'all' } });    // 运行时更新
```

### 核心设计

- **文件默认关闭**：`cfg.fileEnabled` 默认 `false`（原为 true）。出现 `file:{…}` 对象（哪怕 `{}`）即自动开启；`file: false` 显式关闭优先级最高。全键都有默认值。
- **全局 log 用 Proxy 门面**：ESM `const` 导出无法重新赋值，故 `log` 是 `Proxy`，get/set/has 全部转发到「当前注册的实例」，函数自动 bind。保证 `import { log }` 拿到的是稳定引用。
- **实例 file 配置 = 替换而非叠加** → 天然不重复记录（一个 `_emit` 最多一次 `fileTransport.write`）。
- **通道独立级别**：`consoleLevel`（全局）/ `file.level`（文件配置内）。新增 `parseLevelOpt()` 归一为**白名单数组**、`levelPasses()` 判定：
  - `'info'` → 该级别及以上；`'all'`/`'*'` → 全部；`['info','error']` → 仅这两级；`'warn,error'` → 等同数组；`'off'`/`null` → 关闭
- **`traps.js` 强制留档**：`log.config({ file: { name:'process', level:'all', error:true } })`，崩溃记录不与全局 file 开关耦合。
- **新增 `resetLogConfig()`**：清空 `runtimeOverrides` 再重载（测试隔离必需，因为覆盖会累积）。

### 踩坑与修复（关键）

**v0.4.1 修复的语义 bug**：全局 `level='info'` 时，即使实例写了 `file.level='all'`，`debug`/`trace` 仍落不了盘——`'all'` 形同虚设。根因是两道门：
1. 普通级别分支 `else if (lv < threshold) return;` 在通道判定**之前**就把低级别丢了；
2. debug/trace 分支要求必须有 `LOG_DEBUG` 关键词才放行。

修法（`logger.js`）：
- 普通级别：`lv < threshold && !consoleExplicit && !fileExplicit` 才 return；
- debug/trace：新增 `else if (consoleExplicit || fileExplicit) debugUnlocked = true;`。

**收敛成一句话的语义**：*全局门槛管「默认行为」，显式通道配置优先。*

**Git 踩坑**：`git push` 后 `origin/main` 引用丢了（`status` 显示 `[gone]`），`git ls-remote` 证明远端其实已有提交。`git update-ref` 写不进 `.git/refs/remotes/`（目录被删后重建也无效），最后用 `printf '<sha> refs/remotes/origin/main\n' > .git/packed-refs` 恢复跟踪。

**npm 发布踩坑**：`npm publish` 命令会触发敏感审批，超时后命令被拦截；但需用 `npm view <pkg> version` 确认是否实际已发布——本次两次都是「审批超时但实际已成功」。发布前务必先 `npm view` 查线上最新版，避免重复发布浪费版本号。
