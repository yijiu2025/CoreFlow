### 最重要的发现（新，且是 P0）

**① `measure-load-budget.mjs` 的 CDP 口径看不见 SW 流量 —— 之前的"首访 780 KB"结论是用错口径的。**
它的 `Network.enable` 挂在 page target，而 SW 的 install（`precacheAndSet → addAll`）跑在**独立 ServiceWorker target**。
于是 `--block-sw` 与不屏蔽两轮数字**一字不差**（都是 214.0 KB），还报"清单里首访不会请求的有 0 项"。
实测（caches 遍历）：SW **确实全量下载了 76 项 / 780 KB**，`storage.estimate` 显示 834.3 KB 占用。
⇒ 登录页真实首访 ≈ **994 KB**，其中 **78% 是这次根本用不到的预取**（页面自身按需只要 214 KB）。

**② SW 的 `NavigationRoute` 会劫持一切同源导航 → 破坏设备码授权页。**
产物 `sw.js` 末尾：`s.registerRoute(new s.NavigationRoute(s.createHandlerBoundToUrl("index.html")))` —— 构造时**没传 options**，
workbox 默认 `{allowlist:[/./], denylist:[]}` ⇒ **所有同源 GET 导航**都命中，且 `createHandlerBoundToURL` 是 precache-first。
实验：同一 URL `/__sw-probe__.html`（服务器上真实存在的静态页）
- 无 SW：HTTP 200，拿到标记页 ✅
- 装 SW 后：HTTP 200，但内容是**预缓存的 index.html**（SPA 骨架）❌

本项目**单服务同源**（`docker-compose` 只有 `nodeservers:local`；Fastify `@fastify/static` 同时发前端 `public/` 与 `/oauth2.1/*`），
而 `device.service.js` 里 `verification_uri = ${issuer}/device`、`config.js` 的 `issuer` 与前端**同 host** ⇒
`/oauth2.1/device`（`reply.type('text/html')` 的设备授权页，用户必须用浏览器导航打开）**必被顶成登录页** → 设备码授权流程不可用。

**③ 其他风险**：`registerType: 'autoUpdate'`（skipWaiting+clientsClaim）⇒ 页面停留期间 SW 静默接管，
旧页面再动态 import 旧 chunk 时新 SW 缓存已换（`cleanupOutdatedCaches`）→ `Failed to fetch dynamically imported module`；
本仓主题/版式大量用 `import.meta.glob` 懒加载，这条尤其高危。

**④ 收益错配**：登录页是低频入口闸门，且大量访问来自新浏览器/换设备/无痕（缓存完全无效但首访成本照付）。
manifest 亦与产品语义错位（`start_url:'/'`、`display:'standalone'`、`lang:'en'` 而 html 是 `zh-CN`、`theme_color:'#4f46e5'` 是旧设计）。

### 待用户定夺（未动手）

② 彻底移除 VitePWA ③ 保留 SW 但加 `navigateFallbackDenylist` + 收窄 `globPatterns`。

## 决策落地：oauth21 整体移除 PWA（用户选方案 A）

用户回复「A」= 彻底移除。关键前提：**这不是改规范迁就实现，而是把实现改回规范** ——
`docs/frontend/PWA_GUIDE.md` §一 本来就写着「**不适用**：纯登录页（oauth21 用完即走，安装价值低）」，
即此前的集成一直在违反自家规范。

### 落地四件（缺一不可）
1. 删 `VitePWA`（含 `workbox.globIgnores` / `manifest` / `registerType`）。
2. 回滚 `lazyThemeDir()` 那套产物路径前缀（`LAZY_THEME_DIR` / `BUILTIN_THEME_PKG` / `THEMES_SRC` /
   `normalizeId` / `themedFileNames` + `build.rollupOptions.output` 的两个钩子）—— 它**唯一**的存在理由
   就是给 `globIgnores` 精确匹配；SW 没了它就是纯复杂度。产物回到默认 `assets/`。
3. **留一次自毁迁移** `oauth21/public/sw.js`（顶替 `/sw.js` 这个 URL，靠浏览器原生 SW 更新检查被取到）：
   install→`skipWaiting`，activate→`claim` + 清空全部 Cache Storage + `registration.unregister()` +
   让 window clients 重新导航。**不注册任何 fetch handler**。
   ⚠️ 光删配置**清不掉**已装过 SW 的浏览器（它永不回源），这一步最容易漏。
4. 关卡改写（旧判据正好反了，见下）。依赖：`oauth21/package.json` 删 `vite-plugin-pwa`。

### 关卡
- 🆕 `verify-no-pwa.mjs`（无浏览器，17 项）：A `index.html` 无 manifest/SW 注入 · B 产物无
  `manifest.webmanifest` / `workbox-*.js` / `lazy-theme/` / workbox 运行时符号 · C `sw.js` 只能是自毁版
  （含三件套、不含 `precacheAndRoute` / `NavigationRoute` / 清单字面量）· D 惰性 chunk 仍在且回到 `assets/`。
- 🆕 `poison-verify-no-pwa.mjs`：植 4 类毒（manifest link / manifest.webmanifest / lazy-theme/ / workbox 风格 sw.js）
  → **10 类断言全部被点亮** + 还原后全绿。
- 🆕 `verify-sw-migration.mjs`（Playwright，8/8）：往产物放「假老 SW」（留缓存 + 劫持导航）先**复现 P0**，
  再 `register('/sw.js')` 让真自毁脚本接管**同一 scope**（＝老用户真实升级路径）→ 断言缓存清空 + 注销 + 导航回源。

  加「历史脚本，需带 PWA 的旧产物」头注。

### 本轮踩的坑（都已修）
1. 🔴 **workspaces 共用根 `node_modules`**：`npm install` 后我以为 `vite-plugin-pwa` 没删干净，就把包体 `mv` 走 ——
   结果它**仍被 `posecraft` 依赖**（`npm ls` 才发现），差点弄坏 posecraft 构建。**删依赖前必 `npm ls <包>`**。
2. ⚠️ **行尾认知是错的**：此前以为"本仓均 CRLF、Write 必写 CRLF"。实测 258 个文件：**113 纯 LF / 142 全 CRLF / 0 混用**；
   配置与脚本一律 LF，`src/` 源码多为 CRLF。且 `core.autocrlf=true` 让 **git 归一化 → 工作区行尾不影响 diff**
   （已验 `git diff --stat` 数字正确）。**别为行尾做批量转换**。
3. ⚠️ 我的关卡自身两个 bug：① 反向断言没剥注释（`sw.js` 注释里有 `NavigationRoute` → 自伤）；
   ② 产物里是 `` `data-mauth-view`:`default` ``（值用**反引号**，我的字符类漏了它 → 一个包名都提不出来）。
4. ⚠️ `verify-sw-migration` 断言 `<div id="app">` 精确串假红 —— Vue 3 挂载后会加 `data-v-app` 属性。
5. ⚠️ `verify-responsive-switch` **假红过一次**（`+31`）：那"新请求"其实是二维码轮询落在统计窗口内。
   修法：`attach()` 只统计**静态资源**（按 `requestWillBeSent.type`），且取基准前等"计数连续两次不变"而非固定 sleep。
6. ⚠️ 删依赖后 dev server 首启会被沙箱拦在"清 `.vite/deps`"（80 文件 > 50 阈值）→ `mv oauth21/node_modules/.vite` 再起。
