### 最重要的发现（新，且是 P0）

**① `measure-load-budget.mjs` 的 CDP 口径看不见 SW 流量 —— 之前的"首访 780 KB"结论是用错口径的。**
它的 `Network.enable` 挂在 page target，而 SW 的 install（`precacheAndSet → addAll`）跑在**独立 ServiceWorker target**。
于是 `--block-sw` 与不屏蔽两轮数字**一字不差**（都是 214.0 KB），还报"清单里首访不会请求的有 0 项"。
实测（caches 遍历）：SW **确实全量下载了 76 项 / 780 KB**，`storage.estimate` 显示 834.3 KB 占用。
⇒ 登录页真实首访 ≈ **994 KB**，其中 **78% 是这次根本用不到的预取**（页面自身按需只要 214 KB）。

**② SW 的 `NavigationRoute` 会劫持一切同源导航 → 破坏设备码授权页。**
产物 `sw.js` 末尾：`s.registerRoute(new s.NavigationRoute(s.createHandlerBoundToUrl("index.html")))` —— 构造时**没传 options**，
workbox 默认 `{allowlist:[/./], denylist:[]}` ⇒ **所有同源 GET 导航**都命中，且 `createHandlerBoundToURL` 是 precache-first。
实验：同一 URL `/__sw-probe__.html`（服务器上真实存在的静态页）
- 无 SW：HTTP 200，拿到标记页 ✅
- 装 SW 后：HTTP 200，但内容是**预缓存的 index.html**（SPA 骨架）❌

本项目**单服务同源**（`docker-compose` 只有 `nodeservers:local`；Fastify `@fastify/static` 同时发前端 `public/` 与 `/oauth2.1/*`），
而 `device.service.js` 里 `verification_uri = ${issuer}/device`、`config.js` 的 `issuer` 与前端**同 host** ⇒
`/oauth2.1/device`（`reply.type('text/html')` 的设备授权页，用户必须用浏览器导航打开）**必被顶成登录页** → 设备码授权流程不可用。

**③ 其他风险**：`registerType: 'autoUpdate'`（skipWaiting+clientsClaim）⇒ 页面停留期间 SW 静默接管，
旧页面再动态 import 旧 chunk 时新 SW 缓存已换（`cleanupOutdatedCaches`）→ `Failed to fetch dynamically imported module`；
本仓主题/版式大量用 `import.meta.glob` 懒加载，这条尤其高危。

**④ 收益错配**：登录页是低频入口闸门，且大量访问来自新浏览器/换设备/无痕（缓存完全无效但首访成本照付）。
manifest 亦与产品语义错位（`start_url:'/'`、`display:'standalone'`、`lang:'en'` 而 html 是 `zh-CN`、`theme_color:'#4f46e5'` 是旧设计）。

### 关键决策/教训

- 🔴 **设备词汇表从 theme-core 下沉到 `oauth21/src/theme/devices.ts`**：内核只留"设备名是字符串"形态约定，
  `asThemeDevice`/`THEME_DEVICES`/`DEFAULT_THEME_DEVICE` 全随应用走。内核 `index.ts` 里还留这些名字会让
  内核绑定某应用词汇表 —— 违反"内核可被任意前端复用"。
- 🔴 **mini 判定优先级必须高于视口 mobile**：分发器早先顺序是「显式 isMobile → mini 来源 → 视口」，
  而 devices.ts 最初把 mobile（含视口）排在 mini 前 → `?from=mini`+窄视口会误判 mobile。修正为
  mini 排 mobile 前，且 mini 的 match 排除 `explicitMobile`（显式 isMobile 压过 from=mini）。
- 🔴 **`deviceContext` 必须接收响应式 viewportIsMobile**：`isMobileViewport()` 是一次性快照，塞进
  computed 会丢掉 matchMedia 响应（拉宽不切回桌面）。分发器传 `isMobileDevice.value`。
- 🔴 **关卡 PAGES 枚举不能用「含 createViewRegistry(」识别页面**：页面工厂 `page.ts` 自己也调它，
  会把工厂误当成名叫 "page" 的页面 → 关卡去读 `view/app/page/index.vue` 崩溃。改判 `defineThemePage(` + 排除 page.ts。
