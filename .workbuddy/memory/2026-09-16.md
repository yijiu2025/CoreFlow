## IS_TTY 收敛：index.js 改为复用 colors.js（提交 `ba356b2`）

用户追问「index 里面的是不是可以移除掉了」——**不能删，但应该改成复用**。

### 判断依据

`IS_TTY` 在 `index.js` 里只剩**一个**真实用途：决定要不要执行 `chcp 65001`。
这与颜色**是两件事**：

- 颜色问题 → `chcp` 无关，已由 `colors.js` 按 TTY 降级，直接插值 `C.xxx` 即可
- `chcp` 改的是**终端代码页**，属"非颜色类的终端能力判断" —— 无终端的进程执行它是无意义的

所以正确做法是保留判断、但**复用** `colors.js` 已导出的 `IS_TTY`，
而不是删掉整段（删掉会导致 docker/pm2 里也去跑 chcp）。

### 改动前的验证（必须先做）

两处判断写法其实**不同**，需确认等价才敢替换：

```js
index.js  : process.stdout.isTTY === true
colors.js : typeof process !== 'undefined' && process.stdout?.isTTY === true
```

探针在 `true` / `undefined`（管道）/ `false` 三种取值下对比 → **三者取值完全一致**，可安全复用。
（差异只在浏览器/无 process 的边缘环境，Node 服务端入口恒等价。）

### 结果

- `index.js`：删本地读取，改 `import { C, IS_TTY } from './src/utils/colors.js'`，
  悬空的 JSDoc 改写成挂在 `chcp` 段上的行注释（解释"为什么这里用 IS_TTY 而非颜色开关"）
- `colors.js`：文档补充 `IS_TTY` 的导出用途
- **全仓 `process.stdout.isTTY` 读取点：2 处 → 1 处**（仅 `colors.js`）

「TTY 判断只允许出现在 `utils/colors.js`，其它处须 `import { IS_TTY }`」
