### 🔴 顺带挖出一个高危"静默失效"：生产构建根本没删 console

`vite.config` 改 `.ts` 纳入类型检查后立刻报错 —— `build.esbuild` **不是 Vite 8 的合法字段**。
实测：产物里残留 **28 处 `console.*`**（源码共 33 处），也就是说「防 Error 堆栈泄露到 DevTools」
这条**保护措施长期根本不存在**。

成因是"三重静默"：① Vite 8 改 Rolldown+Oxc，`build.esbuild` 失效（顶层 `esbuild` 亦 deprecated→转 `oxc`）；
② config 是 `.js`，从不参与 `vue-tsc -b`；③ 构建 exit 0，配置被忽略但**没有任何信号**。

修法：`build.rolldownOptions.output.minify.compress.dropConsole = true`（Oxc 的等价项，
即 esbuild `drop:['console']` / terser `drop_console`）。**不要改用 `build.minify:'terser'`** ——
那会牺牲 Oxc（比 terser 快 30~90x）。修后残留 **28 → 0**，毒丸（`dropConsole:false`）→ 回到 28。

### 收口做法（新建 `src/types/external.ts` 作为外部边界唯一入口）

1. **SDK 全局窄接口**：`declare global { interface Window { hcaptcha?: HCaptchaSdk; turnstile?: TurnstileSdk; ... } }`。
   两接口只声明**实际调用**的成员（hCaptcha: render/execute；Turnstile: render/reset/execute），
   不照抄 SDK 全量 API —— 保持窄，SDK 大版本改签名才会在这里暴露。
   ⇒ 替掉 17 处 `(window as any).x`（useHCaptcha 7 + useTurnstile 7 + 相关）。
   关键收益：`window.hcaptcha` 可选 → **类型安全判空**，不再 `(window as any).hcaptcha && ...`。
2. **登录响应 zod 判别联合**：`loginResponseSchema = z.discriminatedUnion('action', [...])` +
   `parseLoginResponse(raw)` 返回三态 `{kind:'action'|'success'|'unknown'}`。
   一处定义同时得到**运行期校验 + 编译期 narrowing**。
   🔴 关键：`kind:'unknown'` 分支以前是「`as any` 读不到字段就静默传空对象给父窗口」，
   现在**明确报错**（"登录响应格式异常"）—— 这正是评审要防的"后端字段变了下游零提示"。
3. **其余收口**：`pickRedirectUrl()`（授权跳转，顶层或 data 嵌套一层）· `parseQrStatus()`（二维码）。
