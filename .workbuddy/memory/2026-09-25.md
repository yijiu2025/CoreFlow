## oauth21 四级主题结构定稿 + tokens 收窄为扁平值（提交 f9897cc）

用户原话：「版式*颜色这么多组合， tokens: 不需要light和dark，只需要一组值就好了。」

### 做了什么

1. **四级主题结构**：`themes/<包>/<设备>/<页面>/[<版式>/]colors/<配色>/`。
   注册表键 = **五段复合键** `包/设备/页面/版式/配色`；base 版式用 `BASE_VIEW_ID='base'` 占位。
   两套 glob 合并：base 5 段 + 变体 6 段。
2. **五色并列**：`black`/`white`/`blue`/`cyan`/`rainbow` —— 同列表、同优先级、**无明暗兼职**。
   旧 `mono`/`ocean`/`sky` 全部删除或改名（`ocean`→`cyan`，`sky`→`blue`）。
3. **🔴 tokens 扁平化（本次核心）**：
   - `ThemeTokenOverrides` 由 `{ light?, dark? }` 收窄为 **`Record<string, string>`**。
   - `SanitizeResult` 由 `{ light, dark, rejected }` → **`{ tokens, rejected }`**。
   - 删掉 `activeOf()`（原来 `isDark ? {...light,...dark} : light`）。
   - `applyThemeLayers(layers)` / `applyThemeTokens(overrides)` **去掉 `isDark` 参数**。
   - store 的 watch 变成 `[themeTokens, externalTokens, activeDevice, isDark]`，
     但 `isDark` 只用于 `classList.toggle('dark', dark)`，**不再参与 token 选档**。
   - 明暗与配色**彻底正交**：`mode` 只管基线 SCSS 的 `html.dark`，配色自带完整底色。

### 关键教训

- **⚠️ 块注释里的 `*/` 会提前闭合注释**：写 glob 通配（如 `themes/*/*/*/colors/*/index.ts`）含 `*/`
  → `SyntaxError: Unexpected token '*'`，且**报错行 ≠ 根因行**。本会话踩了两次。
- **配色目录天生是"跨版式各一份"**：同一页的每个版式要各自带一份 colors/，漏了会静默回落。
  本次补齐后共 **21 个颜色目录**（mobile 15 + web 6）。
- **`UD`（unmerged/deleted）状态**：当文件在新目录里已存在、索引里却是"删除+新增"冲突时出现。
  解法 = 对每个文件 `git add -- <path>`（`git checkout` 会报 unmerged）。
- **`git stash pop` 在 rename-tracked 文件上会 unmerged** → 逐文件 `git checkout --` 再 `stash drop`。

### 顺手修的真 bug

- `src/view/app/register/index.vue` 用了 `useRouter` 却只 import 了 `useRoute`
  → `TS2304`。用 clean-HEAD stash 验证是**历史遗留**（非本次引入），补全 import。

## 🔴 明暗切换 = 配色系别切换（合并 mode 与 tone，提交 605f29d，发版 v2.18.0）

### 用户需求（原话，多轮澄清后定稿）
- 「主题切换模式：主类为版式，每个版式下面有好多种颜色分类，黑暗和白色为默认搭配的两种，
  每种颜色要记录好是白色系还是黑色系，比如一个版式有（白，黑，红（黑色系列），蓝（白色系列））」
- 「页面有一个明暗切换有（明，暗，跟随系统），如果是在红色（黑系），点击就切换到白；
  如果是蓝色（白系），就切换黑色」
- 🔴 决定性一句：「**明暗切换就是切换白色和黑色这个色系，不是另一套规则**」
- 「电脑端 base 版式黑白色系切换有问题」

### 根因（读代码定位）
上一版把 `mode`（明/暗/跟随系统）与 `tone`（配色系别）做成**两个独立状态**、各自持久化、
**单向**联动（mode→tone，点色卡不改 mode）。用户心智里它们是**同一个东西**，于是：
1. `isDark` 由 mode 决定、不由配色决定 → 选黑系配色（mode 仍 light）时 html 不挂 `.dark`、
   App 外围 `bg-slate-50` 不切深色 → **桌面 base 黑白切换外围浅色/卡片深色割裂**（用户报的 bug）。
2. 点明暗时若配色已同系别 `syncColorToTone` 直接 return → 视觉"点了没反应"。
3. `mode=light` 但配色 black（或反之）的撕裂态可长期存在。

### 修复（核心不变量：非跟随系统时「明暗 ≡ 配色系别」）
- `isDark` 改为 `computed(() => themeRecordFor().tone === 'dark')`（由生效配色系别派生，函数声明提升 + computed 惰性求值，无需移动位置）。
- `setTheme(id)`（点色卡）**同步 mode**：`toneOfAnyScope(id)` → mode='dark'/'light'，脱离跟随系统。
- 联动改由 `watch(mode)` + `watch(systemDark)` 驱动 `syncColorToTone`（原 `watch(isDark)` 会在"配色切系别"时自循环）。
- `syncColorToTone` 的 fallback 从「字母序第一套（白系落到 blue）」改为**标配 white/black 优先**：
  `ids.includes(standard ? 'white':'black') ? standard : ids[0]` —— 否则全新用户首屏（activeDevice 默认 mobile）
  会把 themeId 切到 mobile 的 blue、web 端回落 white 导致 `data-mauth-theme` 不写。
- 首屏对齐**去掉 hasStoredColor 门槛**：全新用户 + 跟随系统也按系统系别对齐（默认配色字母序 black，
  系统亮就该首屏落 white，否则"跟随系统"形同虚设 + 撕裂）。
- 卡片 `:class="{ dark: isDark || activeTone==='dark' }"` 简化为 `activeTone === 'dark'`（5 个）。

## v2.20.1 路由切换闪屏修复（手机端「立即注册/立即登录」）

### 用户反馈
「手机端立即注册和立即登录切换时会闪一下屏幕。切换不够协调」

### 根因探查（Playwright probe 实测）
`probe-flash-detail.mjs` 高频采样（每 15ms）：
- clickAt=0
- +68ms 路由从 `/m/login` 切到 `/m/register`，旧组件被 unmount
- +105ms 新组件挂载
- **+68ms ~ +105ms 共 37ms 完全空白窗口**（body bg 透出，black 配色下闪黑）

根因 = ① `<router-view>` 裸渲染无 transition + ② 异步 dispatcher chunk 下载延迟 + ③ 无 prefetch 兜底。

### 修复
1. **App.vue 加路由级 `<Transition>`**（核心）
   - `<router-view v-slot={Component}>` 包 `<Transition name="page">`
   - 用**默认模式**（leave + enter 重叠）而非 `out-in` —— out-in 在 chunk 加载延迟
     时会出现 leave 完成后的黑屏窗口（实测 ~40ms）
   - `.route-stage` 绝对定位全屏，让新旧组件**在同一画面里重叠渲染**
   - enter 220ms ease-out / leave 180ms ease-in / 6px 上移
   - opacity 曲线：1 → 0.09（minOp 实测）→ 1，连贯无突跳

2. **多级 prefetch**（消除 chunk 下载延迟）
   - `view/app/<page>/index.vue` 容器 onMounted：import() 另两个 dispatcher chunk
   - `view/web/<page>/index.vue` dispatcher onMounted：import() 三/两个子组件 chunk
   - `goRegister` / `goLogin` / `goForgot` 在 push 前 import() 目标 dispatcher chunk（不 await，与 push 并行）
   - 所有 import 都 `.catch(() => {})` 兜底，失败不阻塞导航

3. **关键设计取舍**
   - 不用 out-in：避免 leave 完成后 enter 起始的 ~40ms 黑屏
   - 用默认模式 + .route-stage absolute：让新旧组件在同一画面里重叠淡入淡出
   - 不在 dispatcher 内层加 `<transition mode="out-in">` 包 `<component :is>`：
     分发器自身要做窄/宽屏异步组件切换，out-in + 异步组件 + 多根节点 = 组件挂不上
     （view/web/login/index.vue L159 已有注释保护这条不变量）

### 实测结果
新增 `.tmp-probe/verify-route-transition.mjs`（9 段全过）：
- login → register：0 空白窗口 / 13 重叠帧 / minOp 0.093
- register → login：0 空白窗口 / 14 重叠帧 / minOp 0.094
- login → forgot-password：0 空白窗口 / 12 重叠帧 / minOp 0.095

之前 37ms 完全空白 → 现在 0ms，完全无感知。视觉上两页 DOM 重叠淡入淡出（mid 截图
清楚显示「欢迎回来」渐隐 + 「创建新账户」渐显）。

### 回归
7 个关卡全过（pure-black / color-by-pkg / view-auto-color /
view-options-v2.18.7 / compact-top-no-line / aesthetics-black / route-transition）；
vue-tsc 0 错；eslint 0 错。

### 关键教训
- **路由切换闪屏几乎都是 chunk 加载延迟**：异步组件越多，闪屏越严重。
  修复组合 = `<Transition>` + 提前 `import()` prefetch，缺一不可。
- **默认模式 vs out-in**：异步组件场景默认模式更稳（leave + enter 重叠渲染，
  用户始终有内容可见）；out-in 仅适合静态组件场景。
- **.route-stage absolute 全屏是默认模式必备**：让新旧组件在同一画面重叠，
  否则两个组件在文档流里堆叠 → 父容器高度跳动 → 滚动条突现。

## register 页 standard/mini 容器+版式拆分（v2.22.0）

### 落地
- `StandardRegister.vue` / `MiniRegister.vue` 从「业务+UI 单体」拆成业务容器（对齐移动端 app/register 标杆 + login 范式）。
- 容器：业务 JS 留守（校验/查重/发码/RSA/回跳），`THEME_DEVICE='standard'|'mini'`，
  静态引入对应版式，`goLogin` 分别指 `/login` / `/mini-login`，activeView+viewEpoch+markRaw 机制。
- 版式：`standard/register/index.vue` 由占位骨架重写为真版式（stdreg-* token 化）；
  新建 `mini/register/index.vue`（mreg-* token 化）+ `colors/{black,white}`（从 standard 复制）。
- **两步分步**（账号+验证码 → 密码+协议），`TOTAL_STEPS=2`，`nextStep(2)` 即进第二步提交；契约复用不改。
  ⚠️ 与移动端三步不同；两步无需「两次密码一致」中间校验 → 容器**不引入 setFieldError**（否则 lint 报未用）。

### 关键坑
- **PasswordInput 不透传 attrs**：login mini 版式已是「不 v-bind attrs」现状，密码字段靠 handleSubmit 全量校验兜底。
  register 版式同样**不 v-bind** `ctx.fields.password.attrs`（否则 attrs 挂到 PasswordInput 根 div，blur/change 不触发）。
- **register 契约无 `isDark`**（那是 login 契约的字段）→ 版式根别写 `:class="{ dark: ctx.isDark }"`，dark 由 AuthContainer 自己挂。
- **mini 来源判定**：register 靠 `?from=mini`（**无 /mini-register 路由**），与 login 的 /mini-login 路由不同。
  探针 URL 拼接注意 `path` 已带 `?from=mini` 时别再拼带 `?` 的 QS（会 `??` 让 from 变成 `mini?appName=...` 判定失败）。
- **新增 mini/register 目录要重启 dev server**（glob 启动期静态扫描）。

## forgot-password 页 standard/mini 容器+版式拆分（v2.23.0）

### 落地
- `DesktopForgot.vue` + `ResetByCode.vue` + `ResetByLink.vue` 三个「业务+UI」单体，合并拆成业务容器 + 版式。
- 容器：`StandardForgot.vue` / `MiniForgot.vue`（`THEME_DEVICE='standard'|'mini'`，goLogin 分别指 /login / /mini-login）。
- 版式：`standard/forgot-password/index.vue` 占位骨架 → 真版式（stdforgot-* token 化）；
  新建 `mini/forgot-password/index.vue`（mforgot-* token 化）+ colors/{black,white}。
- **两种重置方式**：code 3步 / link 4步，由 `ctx.mode` + `ctx.stage` 驱动，契约复用不改。
- dispatcher 三值化（mobile/standard/mini），renderedDevice 三映射。

### 关键坑
- **mini 来源判定**：forgot-password 靠 `?fromLogin=mini`（register 靠 `?from=mini`，login 靠 /mini-login 路由）——三页各自不同。
- **sed 前缀替换顺序坑**：`s/stdforgot-/mforgot-/g` 先执行后，`stdforgot-root` 已变 `mforgot-root`，
  再 `s/stdforgot-root/mini-forgot-root/g` 匹配不到 → 根类名错成 `.mforgot-root`。
  根类名约定：login `.mini-login-root` / register `.mini-reg-root` / forgot `.mini-forgot-root`。
- **验证码输入框定位**：进入 code 步后邮箱框被 v-if 移除，验证码框是 `nth=0`（不是 nth=1）；
  PasswordInput 通过 inputClass 也带 stdforgot-input class → nth 索引要数清。
- **提交按钮**：`button[type="submit"]` 会匹配到 ThemeToggle 的按钮，需用文本「重置密码」定位。
- forgot 无「下一步」按钮，邮箱验证通过后**自动**进 code 步（useCaptchaFlow 回调）。
