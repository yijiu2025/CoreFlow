# 2026-09-25

## oauth21 四级主题结构定稿 + tokens 收窄为扁平值（提交 f9897cc）

用户原话：「版式*颜色这么多组合， tokens: 不需要light和dark，只需要一组值就好了。」

### 做了什么

1. **四级主题结构**：`themes/<包>/<设备>/<页面>/[<版式>/]colors/<配色>/`。
   注册表键 = **五段复合键** `包/设备/页面/版式/配色`；base 版式用 `BASE_VIEW_ID='base'` 占位。
   两套 glob 合并：base 5 段 + 变体 6 段。
2. **五色并列**：`black`/`white`/`blue`/`cyan`/`rainbow` —— 同列表、同优先级、**无明暗兼职**。
   旧 `mono`/`ocean`/`sky` 全部删除或改名（`ocean`→`cyan`，`sky`→`blue`）。
3. **🔴 tokens 扁平化（本次核心）**：
   - `ThemeTokenOverrides` 由 `{ light?, dark? }` 收窄为 **`Record<string, string>`**。
   - `SanitizeResult` 由 `{ light, dark, rejected }` → **`{ tokens, rejected }`**。
   - 删掉 `activeOf()`（原来 `isDark ? {...light,...dark} : light`）。
   - `applyThemeLayers(layers)` / `applyThemeTokens(overrides)` **去掉 `isDark` 参数**。
   - store 的 watch 变成 `[themeTokens, externalTokens, activeDevice, isDark]`，
     但 `isDark` 只用于 `classList.toggle('dark', dark)`，**不再参与 token 选档**。
   - 明暗与配色**彻底正交**：`mode` 只管基线 SCSS 的 `html.dark`，配色自带完整底色。

### 关键教训

- **⚠️ 块注释里的 `*/` 会提前闭合注释**：写 glob 通配（如 `themes/*/*/*/colors/*/index.ts`）含 `*/`
  → `SyntaxError: Unexpected token '*'`，且**报错行 ≠ 根因行**。本会话踩了两次。
- **配色目录天生是"跨版式各一份"**：同一页的每个版式要各自带一份 colors/，漏了会静默回落。
  本次补齐后共 **21 个颜色目录**（mobile 15 + web 6）。
- **`UD`（unmerged/deleted）状态**：当文件在新目录里已存在、索引里却是"删除+新增"冲突时出现。
  解法 = 对每个文件 `git add -- <path>`（`git checkout` 会报 unmerged）。
- **`git stash pop` 在 rename-tracked 文件上会 unmerged** → 逐文件 `git checkout --` 再 `stash drop`。
