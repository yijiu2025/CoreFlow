## oauth21 四级主题结构定稿 + tokens 收窄为扁平值（提交 f9897cc）

用户原话：「版式*颜色这么多组合， tokens: 不需要light和dark，只需要一组值就好了。」

### 做了什么

1. **四级主题结构**：`themes/<包>/<设备>/<页面>/[<版式>/]colors/<配色>/`。
   注册表键 = **五段复合键** `包/设备/页面/版式/配色`；base 版式用 `BASE_VIEW_ID='base'` 占位。
   两套 glob 合并：base 5 段 + 变体 6 段。
2. **五色并列**：`black`/`white`/`blue`/`cyan`/`rainbow` —— 同列表、同优先级、**无明暗兼职**。
   旧 `mono`/`ocean`/`sky` 全部删除或改名（`ocean`→`cyan`，`sky`→`blue`）。
3. **🔴 tokens 扁平化（本次核心）**：
   - `ThemeTokenOverrides` 由 `{ light?, dark? }` 收窄为 **`Record<string, string>`**。
   - `SanitizeResult` 由 `{ light, dark, rejected }` → **`{ tokens, rejected }`**。
   - 删掉 `activeOf()`（原来 `isDark ? {...light,...dark} : light`）。
   - `applyThemeLayers(layers)` / `applyThemeTokens(overrides)` **去掉 `isDark` 参数**。
   - store 的 watch 变成 `[themeTokens, externalTokens, activeDevice, isDark]`，
     但 `isDark` 只用于 `classList.toggle('dark', dark)`，**不再参与 token 选档**。
   - 明暗与配色**彻底正交**：`mode` 只管基线 SCSS 的 `html.dark`，配色自带完整底色。

### 关键教训

- **⚠️ 块注释里的 `*/` 会提前闭合注释**：写 glob 通配（如 `themes/*/*/*/colors/*/index.ts`）含 `*/`
  → `SyntaxError: Unexpected token '*'`，且**报错行 ≠ 根因行**。本会话踩了两次。
- **配色目录天生是"跨版式各一份"**：同一页的每个版式要各自带一份 colors/，漏了会静默回落。
  本次补齐后共 **21 个颜色目录**（mobile 15 + web 6）。
- **`UD`（unmerged/deleted）状态**：当文件在新目录里已存在、索引里却是"删除+新增"冲突时出现。
  解法 = 对每个文件 `git add -- <path>`（`git checkout` 会报 unmerged）。
- **`git stash pop` 在 rename-tracked 文件上会 unmerged** → 逐文件 `git checkout --` 再 `stash drop`。

### 顺手修的真 bug

- `src/view/app/register/index.vue` 用了 `useRouter` 却只 import 了 `useRoute`
  → `TS2304`。用 clean-HEAD stash 验证是**历史遗留**（非本次引入），补全 import。

## 🔴 明暗切换 = 配色系别切换（合并 mode 与 tone，提交 605f29d，发版 v2.18.0）

### 用户需求（原话，多轮澄清后定稿）
- 「主题切换模式：主类为版式，每个版式下面有好多种颜色分类，黑暗和白色为默认搭配的两种，
  每种颜色要记录好是白色系还是黑色系，比如一个版式有（白，黑，红（黑色系列），蓝（白色系列））」
- 「页面有一个明暗切换有（明，暗，跟随系统），如果是在红色（黑系），点击就切换到白；
  如果是蓝色（白系），就切换黑色」
- 🔴 决定性一句：「**明暗切换就是切换白色和黑色这个色系，不是另一套规则**」
- 「电脑端 base 版式黑白色系切换有问题」

### 根因（读代码定位）
上一版把 `mode`（明/暗/跟随系统）与 `tone`（配色系别）做成**两个独立状态**、各自持久化、
**单向**联动（mode→tone，点色卡不改 mode）。用户心智里它们是**同一个东西**，于是：
1. `isDark` 由 mode 决定、不由配色决定 → 选黑系配色（mode 仍 light）时 html 不挂 `.dark`、
   App 外围 `bg-slate-50` 不切深色 → **桌面 base 黑白切换外围浅色/卡片深色割裂**（用户报的 bug）。
2. 点明暗时若配色已同系别 `syncColorToTone` 直接 return → 视觉"点了没反应"。
3. `mode=light` 但配色 black（或反之）的撕裂态可长期存在。

### 修复（核心不变量：非跟随系统时「明暗 ≡ 配色系别」）
- `isDark` 改为 `computed(() => themeRecordFor().tone === 'dark')`（由生效配色系别派生，函数声明提升 + computed 惰性求值，无需移动位置）。
- `setTheme(id)`（点色卡）**同步 mode**：`toneOfAnyScope(id)` → mode='dark'/'light'，脱离跟随系统。
- 联动改由 `watch(mode)` + `watch(systemDark)` 驱动 `syncColorToTone`（原 `watch(isDark)` 会在"配色切系别"时自循环）。
- `syncColorToTone` 的 fallback 从「字母序第一套（白系落到 blue）」改为**标配 white/black 优先**：
  `ids.includes(standard ? 'white':'black') ? standard : ids[0]` —— 否则全新用户首屏（activeDevice 默认 mobile）
  会把 themeId 切到 mobile 的 blue、web 端回落 white 导致 `data-mauth-theme` 不写。
- 首屏对齐**去掉 hasStoredColor 门槛**：全新用户 + 跟随系统也按系统系别对齐（默认配色字母序 black，
  系统亮就该首屏落 white，否则"跟随系统"形同虚设 + 撕裂）。
- 卡片 `:class="{ dark: isDark || activeTone==='dark' }"` 简化为 `activeTone === 'dark'`（5 个）。
- `MODE_LABELS` 改「明/暗/跟随系统」；`applyTheme(dark)` 改调 `setMode`；`applyThemeConfig` 下发 theme 同步 mode。

## 🔴 圆角统一 + compact 配色补齐（提交 83f5d8f，发版 v2.18.1）

### 用户报「web 版立即注册和立即登录圆角不一样，以注册页为准」
排查过程（重要方法论）：CSS 里两端 CTA 都写 12px、computed 也都 12px、无 zoom/transform ——

⚠️ 排查陷阱：disabled 的 opacity-0.5 + box-shadow 会让浅色按钮的圆角**视觉膨胀**（抗锯齿边缘融入白底），

2. 标准登录页 `.std-field`/`.std-submit-btn` 46px → 44px，与注册页完全对齐（用户要求以注册页为准）。
