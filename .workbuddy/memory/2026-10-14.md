## oauth21 拆分为独立开源仓库 oauth-web（Release 1.0.0）

- **背景**：oauth21（登录授权前端，Vue 3 + Vite）此前被根仓 CoreFlow 跟踪（233 文件），按 retroweb 先例拆为独立仓库。
- **新仓库**：https://github.com/yijiu2025/oauth-web.git（main，初始提交 `02d370a`，annotated tag `v1.0.0`，GitHub Release 1.0.0 已发布，draft/prerelease 均 false）。
- **开源化处理**：
  - LICENSE 用 GPL-3.0 全文（与根仓一致，gnu.org 下载 674 行）；
  - README.md（中文）+ README.en.md（英文）双语，命名沿用 retroweb 的 `README.en.md` 惯例；
  - package.json：`login`→`oauth-web`、`0.0.0`→`1.0.0`、加 `license`/`repository`/`homepage`、删 `private`；
  - **删 `nodeservers: file:..` 依赖**（源码零引用，grep 全库仅 package.json 命中）——否则外部 `npm install` 必失败；
  - lockfile 手清：删 `packages[""].dependencies.nodeservers`、`packages[".."]`（父仓整棵依赖树，lockfile 因此从 340KB 瘦到 ~200KB）、`packages["node_modules/nodeservers"]`（link 记录）；用 Python json 模块保序 + `newline='\n'` 落盘；隔离目录 `npm install --dry-run` 验证 697 包可解析。
  - .gitignore 追加 `*.tar.gz`（排除 oauth21-dist.tar.gz 快照）与 `.mimosa/`（hook 状态目录，git init 后曾被误纳 1 个 json）。
- **坑**：
  1. `npm install --package-lock-only` 在 oauth21 里跑会被 **workspace 根规则接管**（父 package.json workspaces 含 oauth21），还会触发父仓 prepare>husky；lockfile 重生失败——隔离目录（C:/tmp）复刻 package.json 再生成，或 Python 手改。
  2. 根仓 `git rm -r --cached oauth21` 正常（src/ 的 git rm 坑不波及此处）；提交只动 index，工作区其他脏文件不受影响。
  3. Write 工具的 `/tmp/xxx` 落到 `C:/tmp/`，而 bash 的 `/tmp` = `AppData/Local/Temp`，两者不是一回事；Python 调用要用 Windows 路径。
  4. push 后跑 `fix-packed-refs.mjs <40位SHA>` 同步 refs/remotes/origin/main（需从 ls-remote 取 SHA 作参数）。
- **根仓**：提交 `986e34e`（chore: 拆分）已推 CoreFlow；.gitignore 加 `/oauth21/`（带前导斜杠，同 retroweb 惯例）。
- **Release 凭据**：从 git credential manager 取（`git credential fill` → password=gho_…），REST API POST `/repos/yijiu2025/oauth-web/releases`；release id 412684979。
