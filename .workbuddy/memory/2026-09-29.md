## retroweb 修「显示不全 + 第二步出错」（同日三修）

- 🔴 **route 的 step 号在同层多分支时会重复**（step = depth+1，`1,2,2`），而 RouteSummary 拿它当
  `:key` ⇒ Vue 重复 key，同层第二个分支渲染不出来 = 用户看到的「第二步出错 / 显示不全」。
  修：`RouteStep` 加 `nodeId` + `branchNo`，**key 一律用 nodeId**，展示补「· 分支 N」，CSV 加分支列。
- 🔴 **adopt 重复采纳同一反应会留下孤儿节点**：原实现只在「换了反应」时 `detachChildren`，
  同反应重采纳时旧子节点还在 `nodes` 里 ⇒ stats / 起始物料汇总出现幽灵条目（探针实测 7→9）。
  修：`if (parent.children.length) detachChildren(parent)` —— 只要有子树就先摘再建。
- 🔴 **默认 `heavyAtomThreshold: 10` 让「多次一步」形同虚设**：阿司匹林拆一步后前体普遍 ≤10 重原子，
  全部立刻变起始物料，第二步根本拆不动。改成 **6**（苯环量级，常用可购买口径）。
  另：终止行的「展开」按钮原来是**点了没反应**（predictNode 静默 return）⇒ 改成禁用 + tooltip 说清原因与解除办法。
- 🔴 **分子结构图被裁**：`fitSvg` 只按恒定键长算 px，不知道容器多大；而 `.step-row__mol`(86×58)、
  `.target__mol`(150×120)、`.history-item__mol`(120×88) 都是**定尺寸 + overflow:hidden** ⇒ 大分子切一半。
  修：`drawSmiles` 加 `fit` 选项（宽高 100% + viewBox 等比缩放），`MolView` 加 `fit` prop。
  ⚠️ **两种模式不可互换**：auto 尺寸容器开 fit 会让 SVG 塌成 0 高。已写进 README §五·五。
- **400 也是结构化响应**：Flask `/api/predict` 校验失败返回 HTTP 400 + `{ok:false,error,reasons}`，
  axios 走 catch ⇒ 原来 `fail()` 只抛 error 文案，**reasons（人话诊断）全丢**。
  修：`predict` 的 catch 里若 `payload.ok === false` 就原样返回，行内展示失败原因列表。
- 其他：缩进 `depth*20` 无上限会把整行挤出容器 ⇒ 封顶 `min(depth,8)*18`；SMILES 从单行硬截改成
  两行 clamp + title；画板 canvas 固定 420px 在矮屏会把 dialog 顶出视口 ⇒ `clamp(280px,46vh,460px)`
  + dialog body `max-height: calc(100vh - 210px)`。
- 手法：store 状态机可以用 **esbuild bundle + `--alias:@=./src` + `--define:import.meta.env={}` +
  `--external:axios`** 在纯 Node 里跑（pinia `setActivePinia` 即可，localStorage 未定义会被 try/catch 兜住），
  再直接改 `retroApi.predict` 打桩 —— 比开浏览器快得多，两个 bug 都是这么抓出来的。

## 🔴 retrochimera Flask「模型好像没加载 / GET /api/jobs 无限挂起」—— 三个独立真凶全解（同日补）

用户症状：「执行预测感觉模型没加载、内存不涨；刷新网页要能展示未完成/进行中的任务」。实测把三个**互相独立**的
Windows/Python 坑全部挖出并修复，最后端到端跑通（4 层单步，0 失败）。

- **真凶 1｜worker 不能是 daemon**：模型必须跑在一个**独立、单线程、非 daemon** 的 `multiprocessing.Process` 里。
  我一开始给 worker 加了 `daemon=True` ⇒ 内部 `RuleApplicationServer` 要 spawn 规则子进程时会抛
  `AssertionError: daemonic processes are not allowed to have children`，模型直接加载失败（内存不涨）。
  ✅ 改：worker **非 daemon**（由**仍是单线程**的主进程 spawn，安全）；退出改由 `_stop_worker()` 显式回收
  （`_REQ_Q.put(None)` → `join(30)` → 兜底 `terminate()`）。**架构**：Flask 主进程永不 spawn，只经
  `_REQ_Q`/`_RESP_Q` 两个 Queue 与 worker 通信；任务用 `_MainThreadExecutor.pump()` 回主线程跑。
  ⚠️ 注意：daemon 判定在子进程 spawn 时触发 ⇒ 报错出现在 worker 的 traceback 里，别在主进程找。
- **真凶 2｜主线程别 import 重库**：`jobhub._run` 里原来调 `install_model_hooks()`，它 `from retrochimera... import`
  会把 **torch/syntheseus 整条链**首次拉进 Flask 主进程，GIL 被占满、饿死 Werkzeug 请求线程 ⇒ `GET /api/jobs` 超时。
  而且 hook 打补丁的是「模型所在进程」，模型已在 worker 里 ⇒ 主进程装 hook **毫无作用**。
  ✅ 改：`_run` 删掉 `install_model_hooks()`；主进程启动时**预热 rdkit**（`main()` 里 `import rdkit`，接请求前跑完），
  首个 job 的 validate 不再临时 import。**判据：主线程栈若停在 `get_data`/`import retrochimera` = 本坑。**
- **真凶 3（⭐最隐蔽）｜`Job.snapshot()` 自锁死**：`snapshot()` 在 `with self._lock:` 里调 `self.progress()`，
  而 `progress()` 又 `with self._lock:` ⇒ 同一线程对**非重入** `threading.Lock` 二次获取 = 永久死锁。
  ✅ 改：抽出 `_progress_unlocked()`（假定已持锁），`progress()` 只包一层锁、`snapshot()` 直接调无锁版。
  **判据：`/api/models`、`/api/_threads` 秒回，唯独 `/api/jobs/<id>` 恒超时 = 该 job 的锁被本线程自锁死。**
  （`/api/_threads` 这个「导出所有线程栈」的临时诊断路由是关键破案手段，已留在 app.py。）
- **真凶 4（顺带）｜prediction 是「反应 SMILES」不是前体**：worker 返回 `str(p)` 形如 `reactants>>product`，
  旧 runner 直接 `smi.split(".")` ⇒ 最后一段带上 `">>产品"`，下游当非法分子（校验/建树都炸）。
  ✅ 改：`jobhub` runner 按 `">>"` 切出**反应物侧**再 split；新增 `reaction`/`product` 字段；
  `retroweb/src/types/retro.ts` 的 `PredictCandidate` 同步补可选字段。
- **前端会话续跑**（用户第 2 个需求）：localStorage `retroweb_sessions`（`SESSIONS_KEY`，上限 10），
  `workspace.ts` 加 `sessions/currentSessionId/jobIds` + `persistSession`(400ms 防抖)/`resumeSessions`/
  `resumeLoading`/`loadSession`/`removeSession`；`SessionPanel.vue` 列非 done 会话（运行中/未完成标记），
  `WorkspaceView.vue` `onMounted` 调 `resumeSessions()`，刷新后自动接回未完成的 job 轮询。`vue-tsc -b` 全绿。
- **验证（本次真跑通）**：`app.py` 启动 ~60s 加载 → `[app] ✓ 模型进程已就绪`；单 job 端到端 11.3s（阿司匹林

## 🔴 retroweb 大升级：路线方案切换 + 分析留档复用 + 每步流程 + 大模型工艺分析（同日续）

用户需求（原文）：「每次先预测一步…手动决定哪个继续拆…最后展示一条完整路线，或切换显示同一原料的多条路线；
每次分析结果保留，相同中间体可直接使用；最后每步生成展示流程；再加大模型 api，分析投料顺序/当量/反应结果/副产物/LCMS/核磁」。

**五个能力的落地要点（都有坑，别再重踩）**

1. **确定性 reactionId 是全套设计的地基**：`reactionIdFor(nodeId, precursors)`（djb2 风格哈希）。
   同一前体集合**永远映射到同一 id** ⇒ 方案选择、检测复用、切回复原全部稳定；否则每次重分析 id 都变，
   方案表立刻失效。**任何涉及「同一反应」的判定都必须走这个函数，不许现算字符串。**
2. **「切换方案」= detach 而非删树**：`detached: true` 的节点留在内存、不进 `nodeList`/统计
   （`allNodes` 里能查到）。切回时按确定性 id 把 `parentReactionId` 命中的子节点 `attachSubtree` 回去 ⇒
   **不重跑、不丢既有分析**。若改成删除，用户切回去整棵子树白拆。
3. 🔴 **改「已保存」方案的选择必须 fork 新方案，绝不能就地写**：否则历史方案悄悄变样，
   用户拿去对比的两个方案其实已变成同一条。`syncCurrentScheme()` 检测冲突即 fork，**这是本功能第一号红线**。
4. **`applyScheme` 必须遍历 `allNodes` 而不是 `nodeList`** —— 只看可见节点 ⇒ detached 子树永远接不回来。
   这个 bug 是靠真实 store 集成测试抓出来的（`npm run test:store`），静态看代码看不出来。
   另外方案里的 `want` 若已不在当前候选列表，要从 `node.runs` 历史里**捞回**再物化。
5. **分析留档 = `node.runs[]` + `activeRunId`**：`pushRun/switchRun`，`MAX_RUNS=6`。切 run 要把
   候选、概率、耗时一起回滚（不能只换候选）。
6. **相同中间体复用**：新子节点先 `findReusableNode`（同 canonical SMILES）→ `copyAnalysis`，
   标 `reusedFrom`。**复用 ≠ 重跑模型**（这是用户要的省时间点），但仍允许手动「重新分析」覆盖。
7. **SSE 必须 POST**：要带请求体 ⇒ 不能用 `EventSource`，只能 `fetch` + `ReadableStream` + `TextDecoder`，
   按 `\n\n` 切事件。后端 Flask 侧要 `X-Accel-Buffering: no` + `Cache-Control: no-transform`（防 nginx 缓冲）。
8. **JSON 抽取用花括号配平扫描器**（带字符串/转义状态机），不要正则：模型输出常包 ```json 围栏 + 前后废话，
   正则会在字符串里出现 `}` 时截断。`response_format:{type:"json_object"}` 要发但不保证模型遵守。
9. 🔴 **质量数一律 RDKit 算，LLM 只解读**：prompt 里塞好 `[M+H]+/[M-H]-/[M+Na]+`，明确禁止模型自己算数。
   （`_PROTON=1.007276466621`、`_SODIUM=22.989218`）
10. **localStorage 配额**：分析原始输出落盘前截断 2000 字符；写失败时兜底**剥掉全部 `analyses[].raw`** 保会话。
