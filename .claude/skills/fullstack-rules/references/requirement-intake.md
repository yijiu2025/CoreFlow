# 需求确认规范（新项目 / 新 App）

> 新项目/新 App 的完整前置流程。**在创建任何代码之前必须走完本流程**，
> 禁止跳过提问直接写代码。流程完成后回到 SKILL.md 的"固定执行顺序"开发。

## 流程总览

```
Step 1: 输出需求文档 (.md)
    ↓
Step 2: 逐轮提问确认需求（至少 3 轮）
    ↓
Step 3: 输出最终架构方案
    ↓
Step 4: 用户确认 → 创建 KX 架构文件 (.kx)   ← 按 [kx.md](kx.md) 执行
    ↓
Step 5: 开始生成代码                          ← 回到 SKILL.md 固定执行顺序
```

## Step 1 — 输出需求文档

在创建任何代码之前，先生成一份完整的 **需求文档（`guide/requirements.md`）**，包含：

```markdown
# 项目名称需求文档

## 1. 产品定位

- 一句话描述：这个项目/App 做什么？
- 目标用户：谁会用？
- 核心价值：解决什么问题？

## 2. 功能清单

- 功能 A：描述
- 功能 B：描述
- ...

## 3. 页面规划

- 页面 1：路由 /xxx，用途
- 页面 2：路由 /xxx，用途
- ...

## 4. 数据模型

- 实体 1：字段列表
- 实体 2：字段列表
- ...

## 5. API 接口

- 接口 1：GET /api/xxx，用途
- 接口 2：POST /api/xxx，用途
- ...

## 6. 数据来源

- 外部 API / 本地数据库 / 第三方服务

## 7. 权限设计

- 角色：操作权限
```

## Step 2 — 逐轮提问确认需求

需求文档输出后，**不要直接写代码**。必须通过多轮提问确认需求，每轮 2-4 个问题：

**第一轮（产品定位）：**

- 项目名称和定位是什么？
- 目标用户是谁？使用场景是什么？
- 核心功能有哪些？（列出 3-5 个主要功能点）

**第二轮（功能细节）：**

- 数据模型有哪些？（核心实体和字段）
- API 需要哪些接口？（method + url 列表）
- 前端页面有哪些？（路由列表）

**第三轮（技术选型与约束）：**

- 数据来源？（本地数据库 / 外部 API / 第三方服务）
- 权限设计？（角色 + 权限编码）
- 前端架构？（Vue 3 / React / 其他）
- 是否需要先创建 KX 架构文件？（新项目/新 App 默认需要）

**提问规范：**

- 开放式问题优先（"这个功能期望达到什么效果？"）
- 避免只有"是/否"的封闭问题
- 如果涉及多个方案，列出选项让用户选择
- 每轮结束后，更新需求文档，让用户确认

## Step 3 — 输出最终架构方案

确认所有需求后，输出完整架构方案，包含：

- 项目概述（定位、目标用户、核心功能）
- 页面路由规划（路径 + 标题 + 用途）
- 数据模型设计（实体 + 字段 + 关联关系）
- API 接口设计（method + url + 请求/响应）
- 权限模型（角色 + 权限编码）

## Step 4 — 用户确认后创建 KX 文件

用户确认架构方案后，按 [kx.md](kx.md) 的"编写 KX 文件的步骤"创建 `.kx` 文件，
完成后展示给用户确认，再进入 Step 5。

## Step 5 — 开始生成代码

用户确认架构后，回到 SKILL.md 的"固定执行顺序"开发代码
（curl 验证外部 API → 后端 → curl 验证 → 前端 → 全链路验证）。
